# MingLi 命理知识数据库说明

## 1. 这个目录是干什么的？

`data/` 不是简单的“口诀集合”，而是 MingLi 命理排盘与研究引擎使用的**机器可读知识库**。

它的目标是把传统子平命理中分散在《渊海子平》《子平真诠》《滴天髓》《三命通会》《穷通宝鉴》《神峰通考》等文献中的：

- 月令、日主、五行生克；
- 十神关系；
- 旺衰、通根、透干、会局；
- 正格、变格、特殊格局；
- 用神、相神、喜神、病药、通关、调候；
- 天干五合、地支六合、三合、三会、冲、刑、害、破；
- 合化、合绊、争合、妒合等状态；
- 大运、流年与原局的动态作用；
- 神煞等辅助体系；
- 原典文本及其出处；

整理成可以被程序读取、检索、组合和审计的数据。

**核心目标不是“让程序会背口诀”，而是让程序知道一条规则是什么、来自哪里、适用于什么条件、什么时候不能直接使用。**

---

## 2. 数据库的基本原则

### 2.1 原典与程序规则分开

数据库中同时存在两类内容：

1. **原典证据**
   - 保存古籍原文、章节、来源和校验状态。
   - 例如 `classical_texts.json`。
   - 原文与后世解释不得混为一谈。

2. **结构化规则**
   - 将传统命理思想转化为机器可以执行的条件。
   - 例如“月令优先”“合不等于化”“格局先候选后验证”。

程序规则是工程表达，**不能把程序中的权重、阈值或状态机反过来说成古人原文**。

### 2.2 不把口诀硬化成绝对规则

例如：

- “见合”不等于“必化”；
- “见官”不等于“必贵”；
- “见财”不等于“必富”；
- “身弱”不等于“必贫”；
- “伤官见官”不能脱离制化条件直接判定；
- “从格”必须先检查是否真的达到从势条件；
- 神煞只能作为辅助证据，不能覆盖格局和制化。

因此数据库尽量使用：

**候选 → 条件 → 成立 → 破坏 → 救应 → 岁运触发**

这样的逻辑，而不是单句吉凶表。

## 3. 各文件的职责

## 4. 规则如何进入实际排盘

推荐的计算顺序不是“找到一条口诀然后输出吉凶”，而是：

### 第一层：历法与四柱

确定：

- 节气；
- 月建；
- 年月日时四柱；
- 天干地支；
- 藏干；
- 日主。

### 第二层：基础关系

计算：

- 五行；
- 阴阳；
- 十神；
- 通根；
- 透干；
- 生克；
- 合冲刑害破；
- 三合、三会等。

### 第三层：旺衰与气候

分别建立：

- 旺衰轴；
- 寒暖轴；
- 燥湿轴；
- 五行流通轴。

这些轴不能简单合并成一个“分数”。

### 第四层：格局候选

根据月令、透干、藏干及组合关系生成候选：

- 正官；
- 七杀；
- 财；
- 印；
- 食神；
- 伤官；
- 建禄；
- 羊刃；
- 杂气；
- 特殊格局；
- 从格；
- 专旺；
- 化气等。

### 第五层：成败与救应

继续检查：

- 是否成格；
- 是否破格；
- 是否有救；
- 是否有相神；
- 是否有制化；
- 是否存在多个竞争候选。

### 第六层：用神体系

分别记录：

- 格局用神；
- 相神；
- 喜神；
- 病药；
- 调候；
- 通关。

如果不同体系给出不同方向，不强行合并，而是保留证据链。

### 第七层：岁运

最后加入：

- 大运；
- 流年；
- 原局与大运关系；
- 原局与流年关系；
- 大运与流年关系；
- 原局潜在关系被岁运引动的情况。

这样才能避免把原局静态结论直接复制到每一年。

## 5. 证据等级

数据库沿用项目已有的证据思想：

- **E0**：待核验或仅作占位，不应作为最终依据。
- **E1**：传统命理常见说法，但目前缺少足够可靠的原典定位。
- **E2**：能够定位到传统文献文本或可靠数字底本。
- **E3**：经过多个传统来源交叉验证。
- **E4**：有明确原文、版本、章节和解释链，并经过系统性校验。
- **E5**：经过实际程序测试、案例验证及来源审计的高置信规则。

注意：

**E2/E3/E4 表示文献证据强度，不表示现代科学意义上的“正确”。**

本项目研究的是传统命理知识体系的内部一致性、文献来源和程序化表达。

## 7. 原典扩充的质量控制

本轮新增数据采用“短摘录 + 章节定位 + 来源链接 + E2 证据等级”的方式录入；上一轮 89 条新增记录主要覆盖《子平真诠》第二十三至第四十八篇；本轮再补充 27 条《穷通宝鉴》原文，全部保持在 `original_text` 原文层，不把后世评注混入原典层。E2 的含义是能够定位到公开可靠的数字底本；尚未逐条完成影印本逐字校勘，因此不把这些条目标成 E4/E5。

特别说明：

- 《三命通会》采用可定位到卷五的四库本页面；该书本身的卷次、后刻增入内容等版本问题在总书目中已有说明。
- 《神峰通考》采用维基文库完整页面作为数字核验底本，并把“病药说”与具体格局材料分开保存。
- 《穷通宝鉴》保留传统通行署名，但对其整理史、版本及与《栏江网》的关系保持审慎，不把现代整理本的说法倒灌成古籍原文。
- 原典摘录与程序化规则始终分离；“原文说过”不等于“程序必须这样判”。

## 8. 为什么不把所有“命理口诀”都直接加入？

因为这会迅速把数据库变成一个看似庞大、实际上不可审计的“口诀垃圾场”。

尤其要警惕：

- 网络文章把现代解释冒充古籍原文；
- 后人口诀被错误署名给经典；
- 不同版本文字被混写；
- 某一门派规则被写成“子平唯一规则”；
- 神煞被夸大为决定性因素；
- 单一案例被总结成普遍定律；
- 现代经验权重被包装成古法算法。

因此，本项目宁可少收一条，也不把无法确认来源的句子伪装成经典。

## 9. 关于神煞

神煞数据库的定位是：

> **辅助特征，不是核心判命引擎。**

程序应该先完成：

**月令 → 日主 → 五行 → 十神 → 格局 → 制化 → 用神 → 岁运**

然后再把神煞作为附加证据。

例如天乙、文昌、驿马、桃花、华盖、羊刃等，可以用于解释传统命理文本中的辅助维度，但不能因为某一个神煞出现，就覆盖核心格局判断。

对于来源不能可靠核验的神煞口诀，后续应继续审计，而不是继续机械扩充。

## 11. 最终目标

最终希望形成的不是：

> “输入八字 → 查一句口诀 → 输出吉凶”

而是：

> **输入八字 → 建立结构 → 生成候选 → 检查成败 → 识别病药 → 分离调候 → 叠加岁运 → 检索原典依据 → 输出证据链。**

这样数据库才真正具备研究价值、程序价值和长期扩展价值。


### 本轮新增的审计要求

本轮继续扩充《子平真诠》时，特别增加了“原文 / 后世评注”区分。凡检索结果明确属于徐乐吾等后世评注者的文字，不再标记为沈孝瞻原文，而单独使用注释层记录。这样可以避免“评注被倒灌成原典”的问题。

新增重点包括：

- 《子平真诠》用神配气候得失；
- 用神格局高低；
- 用神纯杂；
- 行运成格、变格；
- 喜忌干支有别；
- 支中喜忌逢运透清。

这些内容用于建立“原局 → 岁运 → 引动 → 成格/变格”的证据链，而不是直接生成固定吉凶分数。
