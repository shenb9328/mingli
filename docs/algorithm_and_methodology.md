# 命理数据库 V3.5：数据模型、算法与校验方法

## 1. 目标

本项目不是把八字口诀堆成一个“吉凶词典”，而是建立一个可追溯、可复算、可审计的规则系统。

核心原则：

1. **文本与解释分离**：古籍原文、现代解释、程序规则不混在同一字段。
2. **来源与证据等级分离**：有来源不等于已经完成扫描页校勘。
3. **规则分层**：月令、日主、藏干、十神、旺衰、格局、调候、合冲刑害、病药、岁运分别计算。
4. **先结构、后结论**：任何单一神煞、合冲或十神不得直接覆盖原局结构。
5. **禁止伪精确**：数据库宁可标记“异文/待核”，也不把现代整理表伪装成古籍原文。
6. **不使用固定吉凶分数**：如果未来加入数值评分，必须明确标记为 heuristic，而不是古典规则。

## 2. 总体计算管线

```
输入四柱
  ↓
历法层：年/月/日/时干支
  ↓
月令层：月支、节气、司令藏干
  ↓
日主层：日干、阴阳、五行
  ↓
藏干层：十二地支藏干及本/中/余气
  ↓
十神层：以日干为参照映射
  ↓
旺衰层：月令 + 根气 + 透干 + 生扶泄耗制化
  ↓
格局层：月令提纲 → 格局候选 → 成败救应
  ↓
用神层：月令用神、顺逆、变化
  ↓
调候层：日主 × 月令 120格矩阵
  ↓
关系层：合、冲、刑、害、破、会局
  ↓
病药层：找失衡点 → 找制化药
  ↓
大运层：运支/运干加入后重新计算
  ↓
流年层：年柱加入后再次重新计算
  ↓
综合解释
```

## 3. V3.2 的核心算法

### 3.1 调候矩阵

《穷通宝鉴》按“十干×十二月”组织调候内容，因此本库固定建立 **10×12=120** 个格位，而不是只保存若干口诀。

每个格位至少包含：

- `day_master`：日主
- `month_branch`：月令
- `tiaohou_priority`：调候优先序
- `primary_use`：首要调候对象
- `secondary_use`：次要对象
- `twelve_growth_stage`：十二长生状态
- `source_refs`
- `evidence_level`
- `verification_status`
- `notes`

这里的“优先序”只是《穷通宝鉴》提要层的结构化表达，**不是最终用神判定**。

### 3.2 十二长生

十二长生作为独立特征计算，不直接等价于现代“强弱分数”。

算法：

1. 根据日主天干查 `twelve_growth.json` 对应序列。
2. 在月令支上查找位置。
3. 得到“长生、沐浴、冠带、临官、帝旺、衰、病、死、墓、绝、胎、养”之一。
4. 该状态只进入旺衰辅助层，不能单独决定格局或吉凶。

### 3.3 十神

十神由三个条件共同决定：

- 五行生克方向；
- 与日干同/异五行；
- 阴阳同/异。

因此程序应由关系函数计算，而不是给每个日主复制一套硬编码表。

### 3.4 旺衰

建议采用“证据集合”而不是简单加减分：

- 月令得令；
- 同类根气；
- 生扶来源；
- 泄耗；
- 克制；
- 透干；
- 合化/冲战等结构变化。

如果以后为了机器检索需要数值化，可以另建 `heuristic_strength_model.json`，不得把数字写进经典规则本身。

### 3.5 格局

格局候选优先从月令提纲产生：

```
月令 → 藏干 → 透干 → 十神 → 格局候选
```

然后检查：

- 是否有相应透干；
- 是否有生扶；
- 是否被冲破、混杂或制化；
- 是否符合该格的成败条件。

“出现正官/七杀/财/印”等十神，不等于自动成格。

### 3.6 用神与调候必须分层

这是数据库最重要的防错规则之一：

- **格局用神**：解决结构成败；
- **调候**：解决寒暖燥湿；
- **扶抑**：解决日主及五行失衡；
- **通关**：解决两行相战；
- **病药**：寻找具体失衡点及制化手段。

这些层可以共同指向同一五行，但不能互相偷换。

## 4. 证据等级

- E0：无可靠证据，不进入可信规则库
- E1：二手现代资料
- E2：多个可靠数字文本交叉核对
- E3：可追溯历史版本，但尚未逐页扫描校勘
- E4：扫描页逐字核验
- E5：两种以上历史扫描版本对校

当前 V3.2 的120格调候矩阵统一采用 **E2**。

原因：调候提要已能通过多份数字文本交叉验证，但尚未逐格完成历史刻本页面级校勘，因此不冒充 E4/E5。

## 5. 为什么采用“120格”而不是“口诀列表”

如果只保存：

> 甲木冬月喜火

程序无法回答：

- 是寅月还是子月？
- 是甲还是乙？
- 火是主药还是佐药？
- 是否还有水、金、木等条件？
- 该规则属于哪一古籍体系？
- 该规则的证据等级是什么？

120格矩阵把“日主”和“月令”显式化，使规则可以被程序稳定检索，也可以与其他规则层做交叉计算。

## 6. V3.4 基础规则层

### 6.1 合化与冲突消解

V3.4 新增 `transformation_and_override.json`。它不把“天干有合”直接改写成“已经化神”，而是采用状态机：

`uncombined → combined → combined_bonded / transformation_candidate → transformed / broken_transformation / uncertain`

判断成化时至少保留以下证据维度：

- 化神是否得令、得势；
- 地支是否对化神提供根、会局或六合支持；
- 天干是否有化神透出或引化；
- 化神是否受克、受泄、受冲破；
- 合干是否有根有助；
- 是否存在争合、妒合及流派差异。

因此，“甲己合土必须辰戌丑未月”不能作为程序的绝对规则。现有《子平真诠》相关材料明确强调天干五合须得地支之助，并按逐月气候、四柱配合判断真化/假化。citeturn0search2turn0search36

“贪合忘冲”也不再作为无条件的 cancel_clash 指令。程序先保留合与冲两个关系，再根据得令、根气、距离、会局、冲破等证据产生“有效/减弱/并存/不确定”状态。

### 6.2 宫位与六亲

新增 `pillars_and_kinship.json`，把：

- 四柱宫位；
- 日支配偶宫；
- 时柱子女/晚景主题；
- 男女命常用六亲十神；
- 流派差异

分开存储。

固定年龄段（例如“1–15岁、16–30岁”）不作为统一古典常量，因为不同命理体系并没有一个足够可靠的单一年龄切分可以覆盖全部流派。程序必须把 age_range 当作可选 variant，而不是基础真理。

### 6.3 十干体性

新增 `ten_stems_nature.json`。它与 `tiaohou_matrix.json` 正交：

- 调候：日主 × 月令；
- 十干体性：某一干自身性质及其典型作用；
- 合化：干干关系及化神条件；
- 病药：把上述结果作为候选证据，而不是单独判吉凶。

《滴天髓》确实提供“天干论”的十干体性材料，例如甲木“甲木参天，脱胎要火”等；但“庚必喜丁、辛极忌丁、戊不怕水、己一见水即泥”这类网络化二次概括不能直接升级为古典硬规则。citeturn0search6turn0search7

### 6.4 基础元数据

新增 `base_primitives.json`，程序不再需要在 Python 中硬编码：

- 十天干五行与阴阳；
- 十二地支五行与阴阳；
- 五行相生、相克关系；
- 相乘、相侮的概念状态。

其中“地支阴阳”作为基础属性，“体阴用阳、体阳用阴”等特殊理论另设 school-specific 层，避免污染基础元数据。

胎元、命宫、身宫暂时只注册为 rule family，不在基础 JSON 中强行选定唯一算法。未来分别记录：

- 起法；
- 输入要求；
- 顺逆规则；
- 边界条件；
- 来源；
- 证据等级；
- 流派。

这比把“三垣”直接写成一个固定公式更可靠。

## 7. V3.5 变格层

V3.5 补充三组高优先级变格：专旺五格（曲直、炎上、稼穑、从革、润下）、从格四类（从财、从杀、从儿、从弱）以及化气五类（甲己化土、乙庚化金、丙辛化水、丁壬化木、戊癸化火）。

“曲直、炎上、稼穑、从革、润下”的五行名目可追溯至《尚书·洪范》等传统五行分类，《三命通会》亦使用这些名称；但把它们进一步组织成子平专旺格的具体成格条件，是后世命理体系的结构化规则，不能把五行本义直接等同于程序中的格局判定。citeturn0search0turn0search3

### 7.1 变格采用候选状态，而非一次 Boolean 命中

变格统一采用：

`formation → supporting_evidence → breaking_evidence → candidate_status`

而不是“条件为真即成格”。所有变格标记 `strict_mode: candidate_only`。引擎只能输出 candidate、supported、conflicted、broken、uncertain 等中间状态，不能仅凭 JSON 条件直接下最终结论。

### 7.2 专旺格

核心不是简单比较五行数量，而是同一五行形成主导性结构，同时日主属于该五行，并检查得令、得根、地支成局、一气集中及有效异气破局。

因此禁止“木超过50%即曲直格”之类纯数量阈值。

### 7.3 从格

共同底层条件是日主极弱、印比无有效根气，并且其他势力形成可从的主导结构。

- 从财：财势主导；
- 从杀：官杀势主导；
- 从儿：食伤势主导；
- 从弱：无单一从势而顺整体强势。

尤其从弱不能理解为“弱就从”，必须先排除有效印比和更明确的从势。

### 7.4 化气格

`五合存在 ≠ 化气格`。

必须先由 `transformation_and_override.json` 判断合、合绊、化神支持、破化、争合、妒合等状态；只有具备足够化神支持，才允许进入化气格候选。

## 8. 当前版本的边界

本版本故意不做：

- 把调候主药直接转换成“吉/凶”；
- 把十二长生转换成固定分数；
- 把神煞作为核心判定；
- 用现代人格/职业标签冒充古典原文；
- 把徐乐吾等后世评注直接标成原作者文本；
- 用一个来源覆盖全部版本差异。

## 9. 后续校勘路线

### E2 → E3

给每个经典条目绑定具体数字底本、卷次、章节。

### E3 → E4

逐条定位历史扫描版页码，并人工/视觉核对字符。

### E4 → E5

对关键条目至少使用两种历史扫描版本做异文校勘。

优先级：

1. 《穷通宝鉴》十干十二月调候
2. 《子平真诠》用神、顺逆、变化、格局高低
3. 《滴天髓》体用、旺衰、病药
4. 《渊海子平》月令、十神、格局
5. 《三命通会》神煞及子平汇编条目

## 10. 数据库质量原则

任何新增规则必须回答五个问题：

1. **谁说的？** author/source
2. **在哪本书？** source_ref
3. **原文还是解释？** text_layer
4. **证据有多强？** evidence_level
5. **程序如何使用？** rule/graph node/heuristic

回答不了其中任何一个问题，就不能把它作为高可信经典规则直接进入核心库。
