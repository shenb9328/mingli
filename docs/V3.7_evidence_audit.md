# V3.7 文献证据链审计

## 目标

V3.7 不增加古籍数量，而是验证：

> 每一条古籍文本、每一条解释、每一条核心规则，是否能够沿证据链追溯到明确的文献来源。

本阶段采用**非破坏性审计**：不自动修改 `classical_texts.json`、`core_rules.json`，先报告问题，再人工修订。

## 三层证据模型

```
clean_texts/
    ↓
classical_texts.json
    ↓
evidence_records.json
    ↓
core_rules.json
```

同时允许：

```
classical_texts
    └── interpretations
```

但解释、后世注疏和工程化计算模型不得被当作原典原文。

## 当前已知的关键审计点

当前 `evidence_records.json` 是一个**独立证据索引**，不能用“文件存在”代替“覆盖完整”。

因此必须区分：

- **嵌入式证据**：`classical_texts[*].evidence`
- **独立证据记录**：`evidence_records.json`

后者应逐步覆盖前者，而不是仅保存少量代表性条目。

## V3.7 必检项目

### A. 古籍文本层

- `text_id` 唯一
- `source_id` 存在且属于 `sources.json`
- 原文非空
- `text_provenance` 完整
- embedded evidence 完整
- E4/E5 必须有可核查版本依据

### B. 独立 evidence 层

每个 `classical_texts.text_id` 原则上应有对应的 `evidence_records.text_ref`。

同时检查：

- evidence 是否孤儿记录
- 是否存在多个相互冲突的 evidence record
- E4/E5 是否有明确版本、位置或扫描依据
- source_id / edition / text_ref 是否一致

### C. 解释层

`interpretations.text_ref` 必须指向真实古籍文本。

并且必须明确：

- 作者
- 朝代/时期
- 注释来源
- 解释对象

特别区分：

- 原典作者
- 后世注家
- 编者
- 校勘者

### D. 核心规则层

每条 `core_rules` 应能够追溯：

```
rule_id
  ↓
text_refs
  ↓
classical_texts
  ↓
evidence
  ↓
clean_texts
```

规则中的 `historical_principles` 不应仅因为 `text_ref` 存在就自动视为正确。

后续还需要增加**文本内容一致性校验**：

> historical_principles.statement 是否确实来自所引用的原文，还是数据库作者的现代概括。

## E4 / E5 的严格定义

证据等级是**文献证据强度**，不是“命理真理等级”。

建议：

| 等级 | 定义 |
|---|---|
| E0 | 未验证 |
| E1 | 传统说法，出处不明确 |
| E2 | 可追溯可靠古籍/数字底本 |
| E3 | 多来源或版本交叉验证 |
| E4 | 原文、版本、章节/位置及解释链完整 |
| E5 | 文献证据完整，并经过程序/案例层验证 |

因此：

> E4 ≠ 科学证明正确。

## 运行

```bash
python3 tools/audit_evidence_chain.py
```

该脚本发现问题时返回非零状态，但**不会修改数据库**。

## 当前阶段原则

1. 不为了增加 E4 数量而升档。
2. 不把徐乐吾、任铁樵等后世注释伪装成原典。
3. 不把工程化权重、阈值、评分模型写成古籍原义。
4. 不因 validator 通过而宣布文献真实性全部通过。
5. 优先修正 provenance，再继续增加规则。

## V3.7 第二阶段：底本实质比对与注疏层剥离 (Phase 2)

第二阶段不仅审计“字段是否存在”，而是执行**底本逐字与归一化比对（Substantiation Audit）**，重点检查四类关键问题：

| 类型 | 审计维度 | 校验逻辑与标准 | 应对处置 |
| :---: | :--- | :--- | :--- |
| **Type A** | **底本真实性 (Authenticity)** | 逐条比对 `classical_texts.text` 是否真实存在于 `clean_texts/` 对应的清洁古籍中 | 未出现者标为 `text_not_in_clean_corpus`，阻断盲目信任 |
| **Type B** | **出处归属一致性 (Consistency)** | 检查 `source_id` 是否与实际出现书目相符（例如引自《三命通会》却标为《渊海子平》） | 标为 `cross_book_source_mismatch`，修正归属 |
| **Type C** | **经文与注疏剥离 (Layer Provenance)** | 检查标记为“经文/原文”的内容是否实际来自后世评注（如任铁樵阐微注、徐乐吾补注或评注） | 标为 `commentary_mislabeled_as_jingtou`，从原典层剥离降入注疏层 |
| **Type D** | **证据等级真实强度 (Proportionality)** | 凡文本未在清洁底本中获得实质印证者，不得虚标 E2/E3/E4 高证据等级 | 标为 `unsubstantiated_high_evidence_level`，坚决降级或归入待考 |

### 运行方式

```bash
# 生成机器可读的完整实质审计报告
python3 tools/audit_evidence_chain.py --json-out V3.7_evidence_audit.json --no-fail
```
